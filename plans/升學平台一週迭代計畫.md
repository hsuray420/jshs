# 升學平台一週迭代計畫

## 依據與目標

本計畫以 `docs/升學平台競品分析與產品規劃報告.md` 為唯一產品方向依據，並以目前專案在 `8e2cbe8` 的實況為起點。目標不是一週內把網站地圖上的每一個遠期功能都假裝完成，而是完成一條可驗收、可使用、可解釋的 P0 核心路徑：

```text
首頁 → 選擇就學區 → 找校科 → 查看資料與來源 → 加入規劃
     → 試算／理解風險 → 挑戰／適中／穩定 → 排序與備註
     → 產生家庭討論摘要 → 送出前核對下一步
```

報告中尚未具備資料或正式規則的功能，仍然要在選單中被清楚標示為「功能準備中」，不在本週用假資料或黑箱推估冒充完成。

## 現況基線

已具備：

- 四個主任務中心與完整桌機／手機選單。
- 15 區入口與資料狀態模型。
- 全區學校 CSV 搜尋；中投區學校詳情頁。
- 中投區積分試算，基北區明確標示規則校核中。
- 基本規劃清單、加入與移除。
- 升學指南分類、文章來源與更新語言。
- Cloudflare 正式部署與 57 項自動化測試。

本週要補上的核心缺口：

- 首頁與舊 legacy guide 的主流程尚未完全收斂到新 `/schools`、`/tools`、`/planner`、`/districts`。
- 學校資料仍偏「搜尋結果」，缺少一致的決策詳情、來源、年度與可比較欄位。
- 規劃器仍是收藏清單，沒有風險分層、排序、理由與下一步。
- 試算結果有分數，但缺少逐項解釋、資料版本、限制與導入規劃的決策語言。
- 家庭摘要、送出前檢核與列印／下載仍未形成可完成的流程。

## 排序原則

優先級依序是：

1. **先讓使用者不迷路：** 每個入口都要進入正確的下一步。
2. **再讓資料可相信：** 每個高風險判斷都要有年度、來源、狀態與限制。
3. **再讓選項可比較：** 學校、科別、學制與通勤要能放在同一個決策脈絡。
4. **再讓規劃可執行：** 收藏要能變成分層、排序、備註、待辦與摘要。
5. **最後才擴展平台：** LINE、PWA、進階會員與全區試算不搶本週 P0。

## 七輪迭代順序

### 迭代 1／第 1 天：核心路徑校正與首頁進度

**任務：** 把首頁變成「我的下一步」，並讓四個任務入口全部導向目前真正可用的 canonical route。

**新增：**

- 首頁目前情境與就學區狀態摘要。
- 首次使用者的「選區 → 查校科／試算／規劃」下一步提示。
- 首頁進度卡：未開始、已選區、已收藏、已完成試算等狀態。
- P0 核心路徑的整合測試。

**升級：**

- 四個首頁 CTA 改接 `/news`、`/schools`、`/tools`、`/planner`。
- 15 區卡片依資料狀態顯示可做與不可做的事情。
- `district`、學年度、資料更新日改成固定的上下文資訊。

**改掉舊的：**

- 不再把 `/it_hs/guide.htm#calculator`、`#analysis`、`?district=...#schools` 當首頁主要行動。
- 保留 legacy guide 轉址與相容入口，但不讓新使用者從首頁進入舊流程。

**驗收：** 新使用者可在三次點擊內到達一個可用任務；所有首頁 CTA 有對應測試；沒有主要 CTA 指向舊 anchor。

### 迭代 2／第 2 天：校科決策詳情與資料信任

**任務：** 把學校搜尋結果由「資料卡」升級成可判斷的學校／校科詳情頁。

**新增：**

- 一眼看懂、學習內容、招生資訊、歷年參考、生活條件、官方來源六個資訊區。
- 適用就學區、學年度、最後更新、資料狀態與來源元件。
- 加入規劃、加入比較、回報資料問題的入口狀態。

**升級：**

- 搜尋結果保留學制、科別、名額與資料狀態。
- 中投區詳情頁欄位與全國搜尋結果使用同一個資料契約。
- 參考分數與招生名額改用「參考」語言，不使用錄取保證。

**改掉舊的：**

- 不再讓地址與校名成為學校頁的主要決策內容。
- 沒有來源或年度的欄位不再以完整資料的樣子顯示。

**驗收：** 任一可用學校項目都能查看來源、年度、狀態、科別與下一步；資料不足時有明確說明，不出現空白誤導。

### 迭代 3／第 3 天：我的規劃工作台 v1

**任務：** 把收藏清單升級為可排序、可分層、可留下理由的決策工作區。

**新增：**

- 挑戰／適中／穩定三層欄位。
- 志願順序與上移／下移操作。
- 「為什麼想選」與家庭討論備註。
- 每個選項的資料缺口與下一步狀態。

**升級：**

- planner API 與資料表支援 tier、sort order、notes 與更新時間。
- 規劃頁由單一清單改成「我的選項／風險分層／下一步」三段工作區。
- 保留現有 cookie planner identity，不在本週強迫登入。

**改掉舊的：**

- 不再只提供「加入」與「移除」兩個動作。
- 不再用建立時間暗示志願順序。

**驗收：** 使用者可以加入至少三個校科、分到三層、調整順序、寫下理由，重新整理後資料仍保留。

### 迭代 4／第 4 天：試算解釋與風險語言

**任務：** 把試算結果由「一個總分」升級為可核對、可理解、可帶入規劃的結果。

**新增：**

- 個人積分摘要：逐項分數、上限、輸入值與資料來源。
- 計算版本、適用就學區、適用年度、更新日與限制說明。
- 挑戰／適中／穩定的結果語言與「影響最大的條件」。
- 將結果送入我的規劃的操作。

**升級：**

- 中投區結果保留既有正式規則計算。
- 基北區及未校核區維持參考／校核中狀態，不產生未核定分數。
- 計算錯誤與欄位缺漏改成可理解的提示。

**改掉舊的：**

- 不再只顯示總分與「完成試算」訊息。
- 不再讓使用者誤解落點為錄取保證。

**驗收：** 使用者看完結果能回答「用哪一區哪一年規則、每項分數怎麼來、結果能做什麼、下一步去哪裡」。

### 迭代 5／第 5 天：比較表與資料缺口

**任務：** 讓候選校科可以被同一套條件比較，降低使用者自行整理表格的負擔。

**新增：**

- 從規劃清單選擇 2–4 個校科進入比較表。
- 學制、科別／課程、名額、參考資料、通勤、來源狀態欄位。
- 缺資料時顯示「待核對」與官方來源，不填入猜測值。

**升級：**

- 搜尋結果加入已選條件、清除條件與加入比較狀態。
- 桌面表格與手機逐校卡片保持同一套欄位語意。

**改掉舊的：**

- 不再要求家長把資料複製到外部試算表才可以比較。
- 不再用單一排名或分數排序所有校科。

**驗收：** 使用者能在一頁看見候選差異，且每個重要數字都能追到年度、狀態或官方來源。

### 迭代 6／第 6 天：家庭摘要與送出前檢核

**任務：** 把規劃結果變成家庭可以討論與核對的文件。

**新增：**

- 家庭摘要：候選校科、分層、排序、選擇理由、疑問與待辦。
- 送出前檢核：就學區、學年度、志願順序、資料狀態、官方簡章。
- 列印／下載摘要；先完成瀏覽器列印版，PDF 服務視時間保留。
- 分享只讀版本的隱私邊界設計；若本週無法完成安全 token，先提供本機列印，不發布公開連結。

**升級：**

- planner 頁面呈現「下一步」而不是只有已收藏資料。
- 重要日期與指南文章能從待辦直接回到相關頁面。

**改掉舊的：**

- 不再把尚未實作的分享／下載按鈕呈現成可用功能。
- 不再讓「規劃完成」等同於「可以直接送出志願」。

**驗收：** 家長可在 10 分鐘內看懂孩子選了什麼、為什麼選、還缺什麼資料，以及正式送出前要回官方核對什麼。

### 迭代 7／第 7 天：整合、品質門檻與正式發佈

**任務：** 把前六輪串成一條穩定的 P0 產品路徑，完成回歸與正式發布。

**新增：**

- P0 使用者旅程 E2E 測試：首頁、選區、搜尋、詳情、試算、規劃、摘要。
- 行動版、桌面版、鍵盤操作、錯誤狀態與資料狀態檢查。
- 版本變更紀錄與未完成 P1 清單。

**升級：**

- 所有頁面的主標、主要行動、上下文、來源、更新日與下一步語言一致。
- 選單、首頁、文章、學校、工具、規劃器使用同一套狀態元件。

**改掉舊的：**

- 移除所有會讓使用者誤以為功能已完成的 placeholder CTA。
- 移除重複、無法導向下一步、只增加頁數的入口。

**驗收：** `pnpm test`、`pnpm run lint`、必要的 E2E 與 smoke test 通過；正式環境路由、資產、主流程均可用；未完成項目有明確狀態。

## 本週明確不做

以下項目保留在 Phase 2–4，不為了湊功能而壓縮 P0 品質：

- 15 區全部正式超額比序試算。
- 黑箱 AI 錄取預測或保證式推薦。
- 完整 LINE 官方帳號、PWA 推播與獨立 App。
- 沒有安全 token 設計的公開分享連結。
- 未經版本化的歷年統計大量匯入。
- 群科百科、五專百科與完整職涯資料庫。
- 會員付費、顧問服務與學校合作商業流程。

## 每輪固定交付格式

每完成一輪，只回報以下五件事，避免跨輪混雜：

1. 本輪完成了什麼。
2. 升級了哪些既有功能。
3. 淘汰／改掉了哪些舊流程。
4. 驗證結果與剩餘風險。
5. 下一輪唯一任務。

每輪都必須：

- 先寫測試或驗收條件，再實作。
- 不破壞既有 legacy 相容入口，但禁止新增依賴 legacy anchor 的主流程。
- 所有來源、年度、狀態與推估限制可被使用者看見。
- 完成後才進入下一輪，不同時偷做下一輪功能。

## 第一輪執行卡

**目前只做：迭代 1／核心路徑校正與首頁進度。**

完成定義：

- 首頁四個任務 CTA 全部指向 canonical route。
- 首頁與就學區頁能說明目前資料狀態與下一步。
- 主要 CTA 不再使用 legacy guide anchor。
- 新增核心路徑測試並通過完整測試套件。

下一輪只有在本輪完成並驗收後才開始：**迭代 2／校科決策詳情與資料信任。**
