# JSHS AI Style Rules

Scan mode: first-time medium-tier scan (118 source files)
Baseline commit: `eb543d0`
Recorded: 2026-08-14

## Golden Files

- `app/page.tsx` — public visual direction: navy/blue decision-platform palette, large editorial headings, generous section spacing, rounded white cards, and task-first calls to action.
- `components/site-header.tsx` — canonical public brand bar and five-item navigation behavior, including mobile navigation and active states.
- `components/hub-page.tsx` — canonical inner-page hero, task-card grid, closing CTA, and shared header/footer composition.
- `public/it_hs/guide.js` — legacy functional engine: domain-grouped DOM functions, URL-driven page state, Cloudflare planner persistence, and a single `DOMContentLoaded` orchestration block.
- `public/design-tokens.css` — single source of truth for public color, spacing, radius, and shadow tokens.

## Naming & State-Control Rules

- React route files keep imports first, then page metadata/constants/types, then the exported page, followed by small local presentation helpers.
- Shared public chrome belongs in `components/site-header.tsx` and `components/site-footer.tsx`; public routes do not invent a separate primary navigation.
- Public copy is task-first and specific: labels name the action users can complete, not an abstract section or implementation detail.
- Static guide behavior remains in `public/it_hs/guide.js`; visual-only work must preserve IDs, `data-page`, `data-page-section`, and existing handler contracts.
- URL hash is the canonical guide page state. District selection comes from explicit URL state first and remembered local state second.
- Planner state keeps local browser cache as an offline fallback and synchronizes the same state shape to Cloudflare D1.
- Cross-surface visual values use `--jshs-*` tokens from `public/design-tokens.css`; page-specific CSS may compose tokens but must not introduce a competing palette.
- API and network boundaries validate inputs, return explicit status responses, and expose a user-safe fallback when Cloudflare data cannot load.

## DONTs

- Do not replace an existing functional destination with an explanatory duplicate page.
- Do not create a second brand, second primary navigation, or disconnected sub-site for the guide.
- Do not rewrite the static guide state engine as part of a visual refresh; preserve behavior and modernize the shell progressively.
- Do not add Google Fonts, CDN CSS frameworks, ad scripts, remote data fallbacks, or other third-party runtime dependencies.
- Do not hardcode a district when the user has not selected one.
- Do not remove official-source, academic-year, update-status, or risk-disclaimer copy from decision surfaces.
- Do not mix unrelated user CSV/import/back-up changes into a presentation commit.

## 2026-08-14 Style Evolution Log

- Primary navigation evolved from five flat destinations to four task hubs: 升學指南、找校科、試算工具、我的規劃. 就學區 is persistent context rather than a competing top-level destination.
- Desktop uses compact Mega Menus for high-volume content; mobile uses a full-screen searchable drawer, four immediate task shortcuts, and five persistent bottom actions.
- Long-tail content stays behind search and category disclosures so future article growth does not enlarge the first navigation layer.
- The search action may focus the search field; the hamburger action must open at the drawer title without changing scroll position.
- A viewport-fixed drawer must live outside filtered or transformed sticky headers, and every repeated district-context label must update from the same selected district.
